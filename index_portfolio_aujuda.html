CASE_001 / aujuda / C → WEB / live
Academic project // C → Web // live prototype

Aujuda!

Um projeto que começou no terminal, como exercício de programação estruturada em C, e evoluiu para uma aplicação web interativa voltada ao cadastro e à busca de animais perdidos. A evolução preserva a ideia original, mas transforma a experiência em algo visual, acessível e publicável.

STACKC + HTML + CSS + JavaScript
INTERFACETerminal → Web responsiva
CONTEXTProjeto acadêmico + portfólio
STATUSDemo web publicada
01 // PROBLEMA

Uma ideia simples para um problema real.

O Aujuda nasceu da proposta de organizar informações sobre animais perdidos em uma comunidade. A ideia central é permitir que uma pessoa registre um animal desaparecido e que outras pessoas possam pesquisar os registros usando as características que conhecem.

ProblemaInformações sobre animais perdidos costumam ficar espalhadas e difíceis de consultar.
ObjetivoCentralizar cadastro e busca em um fluxo simples e compreensível.
02 // PRIMEIRA VERSÃO

A origem: uma aplicação em C.

A primeira implementação foi desenvolvida integralmente em C e executada no terminal. Nela, usuários e animais são organizados em memória e o fluxo principal passa por cadastro, login, registro de animais e busca por múltiplos critérios.

Cadastro de usuárioRegistro de nome, e-mail e senha antes do acesso ao sistema.
LoginValidação do e-mail e da senha cadastrados.
Cadastro de animalNome, espécie, raça, cor e último local em que foi visto.
Busca combinadaFiltros simultâneos por espécie, raça, cor e localização.
Comparação textualBusca por aproximação ignorando diferenças entre maiúsculas e minúsculas.
Interface CLIMenus, validações e navegação pelo terminal.
aujuda.c / primeira versão
$ ./aujuda
Olá! Seja bem-vindo ao Aujuda!

1 Fazer login
2 Realizar cadastro
...
Após autenticação:

2 Fazer uma busca
03 // EVOLUÇÃO WEB

Do terminal para uma experiência visual.

A segunda etapa foi transformar a mesma ideia em uma aplicação web. A versão publicada mantém cadastro e busca como núcleo do projeto, mas adiciona uma interface responsiva, feedback visual, upload de foto e uma navegação mais próxima de um produto real.

Interface responsivaLayout adaptado para desktop e dispositivos menores.
Cadastro com fotoPrévia de imagem para facilitar a identificação do animal.
Espécies flexíveisOpções comuns prontas e campo personalizado quando a espécie não estiver na lista.
Filtros de buscaPesquisa por espécie, raça, cor e local.
Conta demonstrativaCriação de conta e login local para representar o fluxo de autenticação.
Persistência localUso de LocalStorage para manter dados da demonstração no navegador.
Abrir Aujuda ao vivo ↗ Código da versão Web
04 // TÉCNICA

O que cada etapa me fez praticar.

A evolução do projeto permite comparar duas formas diferentes de resolver o mesmo problema: primeiro organizando lógica e dados em C, depois levando essa lógica para uma interface web.

C / StructsModelagem de usuários e animais na implementação original.
Funções e controle de fluxoSeparação de cadastro, login, busca e interface no programa em C.
HTML semânticoEstrutura da interface, formulários, navegação e modais.
CSS responsivoLayout, estados visuais, componentes e adaptação para telas menores.
JavaScriptBusca, cadastro, autenticação demonstrativa, modais e interações da interface.
GitHub PagesPublicação da versão web para acesso direto pelo navegador.
05 // C → WEB

A mesma ideia em duas etapas.

Em vez de substituir a primeira versão, a aplicação web registra a evolução do projeto. A versão em C mostra a construção da lógica; a versão web mostra como essa lógica pode ser transformada em uma experiência mais acessível para quem realmente utilizaria a solução.

VERSÃO ORIGINAL // C
  • Execução pelo terminal
  • Usuários e animais mantidos em memória
  • Cadastro e login
  • Busca por espécie, raça, cor e local
  • Foco em programação estruturada
EVOLUÇÃO // WEB
  • Interface gráfica e responsiva
  • Cadastro de animais com foto
  • Filtros visuais de pesquisa
  • Conta demonstrativa e LocalStorage
  • Projeto publicado no GitHub Pages
06 // PRÓXIMOS PASSOS

O caminho para transformar a demo em um sistema real.

A versão atual é uma demonstração front-end. O próximo avanço seria conectar a aplicação a um backend e a um banco de dados, armazenar imagens em um serviço apropriado, implementar autenticação real e permitir que os registros fossem compartilhados entre diferentes usuários e dispositivos.

BackendAPI para centralizar usuários, animais e regras da aplicação.
Banco de dadosPersistência real dos cadastros, independente do navegador utilizado.
AutenticaçãoContas reais, sessões e proteção adequada das credenciais.
Armazenamento de fotosImagens disponíveis para todos os usuários da plataforma.
